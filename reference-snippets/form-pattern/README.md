# Form Pattern

## Purpose

Reference for reusable form handling based on reactive forms.

## What to reuse from the current project

- validators
- centralized error messages
- submit states
- success and error dialogs
- reCAPTCHA wrapper pattern

## What should be standardized in the next project

- use reactive forms only
- use a consistent error message pattern
- keep payloads typed
- keep forms testable

## Rule

Every new form should support:

- validation
- loading state
- success state
- error state
